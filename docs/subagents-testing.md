# 子代理 Debug 测试指南

## 安装

全局设置版交付目录：`build/test-delivery/subagents-global/`。

- `rikkahub-subagents-global-arm64-debug.apk`：大多数 Android 真机。
- `rikkahub-subagents-global-universal-debug.apk`：同时包含 arm64 和 x86_64，适合不确定架构或模拟器。
- `SHA256SUMS`：校验文件。

包名 `me.rerere.rikkahub.ssh.debug`，沿用项目版本号 3.1.6；与正式版独立安装，不覆盖正式数据。
若已安装不同签名的同包名 Debug 版，请先备份其数据，不要为安装测试包直接丢弃数据。
测试包需自行配置模型，或通过已有导入功能迁移设置。设置备份可能含凭据，勿公开；SSH 加密凭据跨安装恢复可能需要重新填写。

本次未重建 Web 前端，使用项目已存在的静态资源；子代理专用配置和任务卡片在 Android 原生界面。

## 基础配置

1. 配置一个已知支持工具调用的聊天模型，先确认普通聊天正常。
2. 进入「设置 → 模型与服务 → 子代理」。全局总开关默认开启。
3. 确认「自动批准子代理派发」「信任子代理工具执行」均开启：这是默认无需逐次审批模式。普通助手默认跟随全局；如需例外，在这里的「助手继承」或助手本地工具页单独禁用。
4. 保持默认并发、步骤、Token 预算，先不设置 USD 预算。
5. 文件测试只绑定专门的测试工作区；不要先用生产服务器或真实项目。

Android 的通知/日历等系统权限以及账号登录授权仍由系统管理；这些不是模型工具审批。

## 建议测试顺序

### 0. 全局控制与助手例外

新建两个普通助手，确认无需逐个配置即可使用同一组子代理角色。关闭全局总开关后，两者都不能派发；重新开启后，单独禁用其中一个，另一个仍可使用。
两个助手分别绑定不同工作区/MCP 时，子代理不能获得另一个助手的权限。重启后全局配置、角色模型和助手例外应保留。
旧版自定义配置应可在全局页面选择导入，但不能未经选择就覆盖全局设置。

### 1. 无审批与并行

提示示例：

> 请明确调用子代理：并行让两名 reviewer 分别检查我给出的两段简短说明，最后由你汇总，不要修改文件。

预期：不弹派发/工具审批；出现两个任务编号和聊天任务卡片；任务独立完成，父助手能汇总。
如果模型只用文字宣称派发、没有工具调用和任务编号，请检查模型的工具调用能力。

### 2. 只读查找与模型选择

在测试工作区放少量源码/文本：

> 让 scout 列出测试目录并查找字符串 TODO，给出文件路径和行号；不要运行 Shell 或修改文件。

预期：使用原生 `workspace_list_files` / `workspace_search`；不会给只读角色开放 Shell。
将 reviewer 配置成另一个已配置模型，再重复任务，卡片应显示所选模型。

### 3. 父子问答

> 让 worker 先通过 contact_supervisor 询问报告应该使用什么语言，由你回答中文，再让它完成报告。

预期：任务短暂进入 WAITING_INPUT，父助手答复后继续同一个任务，不重新派发。
也可要求父助手不要替你回答，等待你在任务卡片输入项目代号，验证人工回复通道。业务问题不是权限审批。

### 4. 后台与自动汇总

在测试工作区执行只读测试，例如：

> 让 worker 在后台执行 sleep 30 后输出当前目录。你只派发并结束本轮，不等待，完成后由自动汇总机制处理。

预期：父轮次先结束；子任务继续；完成后有通知/自动汇总（需通知权限和系统允许后台运行）。
自动汇总轮不应再派发新任务或修改文件。默认每对话每小时最多 4 次自动唤醒，超过后仍可手动查询任务。
锁屏与后台行为受 Android/厂商限制，这是需要真机重点验证的部分。

### 5. 取消与作用域

启动一个耗时的只读任务，分别尝试任务卡片取消、停止父对话、关闭子代理开关。

预期：先显示 CANCELLING，清理结束后 CANCELLED；不因后台完成又启动新一轮模型调用。
取消不会回滚文件修改，也不能保证终止脱离 SSH 会话的远端进程，所以测试不要使用后台 daemon 或延迟写入生产文件。
切换工作区/目录或转移助手后，旧子任务不能继续使用旧控制器派发新任务。

### 6. 上下文与阶段工作流

给父对话一段事实，然后要求对比 `context=fresh` 和 `context=fork` 的子任务。
Fork 是经过过滤的有界副本，不包含父系统提示词、推理块或文档附件。

再测试：

> 用 subagent_workflow：scout 查找测试代码；两名 reviewer 分别检查正确性和测试；worker 根据报告修改测试目录内文件。

预期：顺序推进阶段；同阶段可并行；后续任务能通过 read_dependency 读取前一阶段报告，而不是仅依赖截断预览。
当前阶段失败或需要回复时，返回当前结果和剩余阶段；继续时不重跑已完成部分。

### 7. 有限递归

使用 coordinator 角色、深度 2；让它拆成一个简单子任务，并等待结果。

预期：任务树显示父任务 ID 和深度；后代只能访问自己的子树。到深度上限后不再提供派发工具。
并发数包含协调者自身，槽位不足会拒绝，而不是无限创建或死等。

### 8. Git 工作树（仅测试仓库）

准备一个干净、至少已有一次提交的测试 Git 仓库，启用 worker 的独立工作树，关闭它的继续委派能力。

> 主对话直接并行派发两个 worker，分别添加不同文件。先不要应用补丁，完成后汇报隔离位置。

预期：父仓库文件不变；两个任务有不同工作树与补丁。
检查后逐项应用，确认两份改动都进入父仓库，但没有自动提交。
脏仓库、冲突、补丁被修改或 HEAD 改变应拒绝；已有代码不应被 stash/强制清理。
工作树与补丁保留，任务记录清理不会删除它们；每仓库最多 8 个托管工作树。

### 9. 检查点恢复

使用可丢弃的测试文件，要求 worker 精确修改一次，再继续分析；在后续模型请求期间结束 App 进程后重开。

预期：已完成工具结果留在上下文中，安全检查点可恢复；不会机械重复已完成的调用。
如果中断点恰在 Shell/写入执行期间，应看到 UNCERTAIN，而不是自动重放。无检查点或权限/模型失效应明确受阻。
恢复最多 3 次，不清零预算。修改了 SSH 连接、工作区或目录后，应拒绝旧任务续跑和补丁操作。

### 10. 预算与日志

降低 Token 预算，运行需要多步的任务，确认出现 BUDGET_LIMIT 后不继续发送新请求/执行下一步工具。
USD 预算需要角色固定模型并填写价格；价格是估算依据，不是账单保证。当前请求和外部工具费用可能不被精确预估。

在卡片中查看日志，确认可看到模型消息、工具输入输出和结束状态；长日志分页且截断有标记。
请不要把包含真实凭据、私人对话或源码的日志直接公开。

## 反馈时请提供

- 手机/Android 版本，APK 架构及是否允许通知。
- 使用的提供商、模型名称（不要提供 API Key 或令牌）。
- 哪一项测试失败、任务 ID、状态、必要的脱敏日志。
- 是否使用 SSH、是否切换过工作区、是否触及预算或系统后台限制。

内部测试没有使用你的真实账号或付费 API；真实订阅兼容性与 Android 后台行为仍需要上述验收。
