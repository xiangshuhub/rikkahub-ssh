# 原生子代理：信任模式、协作与恢复

## 开启

统一入口：**设置 → 模型与服务 → 子代理**。

全局总开关默认开启；普通助手默认跟随全局，新配置默认启用：

- **自动批准派发**：不弹逐次派发确认。
- **信任子代理工具执行**：父助手工具范围内的调用直接执行，不弹工具审批。
- **自动唤醒父助手**及**启动后恢复安全检查点**。

所有角色、模型、预算、并发、恢复、通知和信任模式统一在这里配置。全局页可管理助手例外；助手 → 本地工具仅保留「跟随全局 / 禁用」和全局设置链接。助手不能在总开关关闭时强制开启。

关闭及权限撤销会取消任务并拦截后续操作；其它参数用于新派发和恢复任务。运行中的模型、提示词和上下文保留启动快照，不会被强行改写。

旧版每助手配置保留用于备份和显式导入，不再单独决定运行行为。全局页可选择一份旧角色/运行参数导入，保持当前全局总开关与信任开关，不自动混合配置或把某个助手的固定模型推广到所有助手。

关闭全局开关会取消全部活动子任务；单独禁用助手只影响该助手。角色全局共享不等于共享工具、MCP、工作区或任务访问权限；未指定角色模型时仍继承各自父对话模型。管理助手及已删除的助手不获得委派能力。

系统权限、订阅登录授权、业务信息问答不属于工具审批，仍需正常处理。
应用管理助手不能委派；本功能不会提升应用管理权限、获取父助手没有的工具或绕过 Android 权限。

## 已实现能力

| 能力 | 行为 |
| --- | --- |
| 角色/模型 | 内置 scout、reviewer、worker、coordinator；可编辑角色、模型、提示词、只读限制、工具白名单和递归权限 |
| 前台/后台/并行 | 一次派发 1–4 项；后台返回任务回执，主对话可结束；可等待、查询、取消任务树 |
| 聊天任务卡片 | 聊天中实时查看状态、结果、问题、继续执行、日志和 Git 补丁；全局子代理页可查看全部助手任务及归属 |
| 父子问答 | 子代理通过 `contact_supervisor` 提问；父助手用 `subagent_reply` 答复，用户也可在卡片直接回复；继续原任务，不用重新派发 |
| 自动汇总 | 后台完成或提问后通知用户；父模型空闲时可自动收到带来源标记的事件 |
| 上下文 | 默认独立上下文；`context: fork` 提供经过过滤、最多约 64000 序列化字符的父上下文副本 |
| 阶段工作流 | `subagent_workflow` 支持顺序阶段 + 每阶段并行任务，前一阶段的报告通过显式依赖转交 |
| 有限递归 | 仅勾选“允许继续委派”的角色可继续派发；默认深度 2，最多 3；后代权限不能扩张 |
| 日志/检查点 | 保存模型请求消息与响应、工具输入输出、结束事件；保存可恢复的子对话和工具完成状态 |
| 用量预算 | 同一控制器任务组及其后代共享 Token/可选 USD 估算预算，发请求前预留，有报告时回填 |
| Git 隔离 | 角色可使用独立 detached worktree；捕获包括新文件的补丁，校验后应用；不自动提交或删除工作树 |
| 中断恢复 | 进程重启后恢复安全检查点；完成的工具结果保留，不因恢复而机械重放已完成的调用 |

### 只读角色也能查找代码

父工作区新增 `workspace_list_files`、`workspace_search` 两个原生只读工具，不依赖模型拼接 Shell：

- 列目录有分页和后端截断提示。
- 搜索按字面匹配，最多 200 个文件、100 个目录、深度 6、10 MiB、20 秒、50 条结果。
- 跳过常见构建目录、二进制/超大文件；不完整结果明确标记 `partial`，不把“未找到”冒充全仓库结论。
- Scout/Reviewer 可继承这些工具，但仍不能使用 Shell、写文件、JS 或未知 MCP。

Worker 只使用父助手已启用的工具。信任模式会取消这些工具的逐次确认，但不会绕过只读角色、白名单、所属会话或系统权限。

## 工具协议

### 派发

```json
{
  "tasks": [
    {"agent": "scout", "task": "查找相关实现，返回路径与证据", "context": "fresh"},
    {"agent": "reviewer", "task": "检查提供的方案，不修改文件", "context": "fork"}
  ],
  "background": true
}
```

`subagent_dispatch` 中每项还可指定：

- `model_id`：已启用、已配置模型的 UUID 或精确无歧义名称。可覆盖角色默认模型；USD 预算开启时，必须匹配已固定且已定价的角色模型。
- `tools`：进一步收窄继承工具。`[]` 禁用继承的外部工具，监督/显式依赖通道仍可用。
- `context_from`：最多 4 个当前控制器有权读取的、已结束任务 ID。子代理只获得这些报告的 `read_dependency` 分页读取能力，不获得访问其他任务的权限。

Fork 不复制父系统提示词、记忆注入、未执行工具、原生子代理编排工具、推理块和文档附件；保留有界文本、图片及已完成普通工具结果。重要背景仍应写入 task。副本可能被裁剪，不等于完整继承父会话。

### 管理

- `subagent_status`：省略 ids 列出本控制器可见任务；指定 ids 查看结果/问题。
- `subagent_wait`：最多等待 60 秒；遇到 `WAITING_INPUT` 提前返回，答复后可再次等待。
- `subagent_reply`：以任务 id + 精确 `question_key` 回复；过期、重复、越权回复均拒绝。
- `subagent_cancel`：取消目标及其后代，不回滚已经发生的副作用。
- `subagent_resume`：恢复安全检查点，最多 3 次运行；保留上下文、步骤、工具次数和预算累计。
- `subagent_trace`：按字节 offset 读取 64 KiB 日志页。
- `subagent_capture_patch` / `subagent_apply_patch`：操作所属任务的隔离补丁，逐项报告成功或失败/不确定，不把部分成功隐藏成整体回滚。

模型侧任务访问绑定 **父助手 + 父对话**；子控制器进一步限定为自己的后代。显式转交的依赖报告只读，不带取消/恢复权限。工作区绑定、目录或助手归属变更会取消旧子任务并作废旧控制器；连接配置身份变化会拒绝后续操作/恢复。

### 阶段工作流

```json
{
  "stages": [
    {"tasks": [{"agent": "scout", "task": "定位问题和相关测试"}]},
    {"tasks": [
      {"agent": "reviewer", "task": "检查正确性"},
      {"agent": "reviewer", "task": "检查测试遗漏"}
    ]},
    {"tasks": [{"agent": "worker", "task": "根据已核验报告实施修复并验证"}]}
  ]
}
```

最多 8 阶段、16 项任务；每阶段最多 4 项。阶段间自动转交报告 ID，子代理可用 `read_dependency` 获取完整保留报告，不能仅凭截断预览下结论。
失败、部分完成或提问会暂停流程，返回当前阶段结果、当前阶段配置和剩余阶段。先处理当前阶段，再明确继续剩余阶段；不重跑已完成工作。
这是有界声明式工作流，不执行任意 JavaScript。父进程中断后恢复的是子任务检查点，不盲目重放整段工作流程序；父助手需核对任务状态再继续剩余阶段。

## 自动唤醒与通知

- 使用独立通知频道，通知不展示任务正文；Android 拒绝通知权限时，卡片仍可查看状态。
- 完成/提问事件有持久化投递标记和队列去重；不唤醒已删除、已转移、已停止的父对话，不自动恢复用户暂停的输入队列。
- 默认每个对话每小时最多 4 次自动唤醒；每次最多 8 次模型请求、输出最多 2048 tokens，不启用应用层自动重试。
- 自动轮只能查询、等待和回复既有子任务；不能派发新任务、恢复任务、执行工作区修改或调用模型原生工具。
- 投递采用“先记录再发送”，避免崩溃后的重复付费唤醒；极端中断可能只保留卡片而未完成自动汇总，可主动询问状态。
- 子请求及自动汇总在用量统计中分别显示。自动汇总属于父模型用量，不包含在子任务组的 USD 估算预算中。

## 预算与运行上限

默认并发：同一父对话 3 个、全局 8 个；可配置对话并发 1–4。槽位不足返回明确拒绝，不偷偷绕过上限。

- 每个控制器工具集最多尝试启动 16 项；父对话每小时最多 32 个逻辑启动记录。
- 默认每子任务 12 次模型请求、300 秒、单次输出 2048 tokens；最多 64 次工具执行。
- 默认任务组共享 100000 Token 预算，包含后代；恢复不清零累计。
- 用量未知时按消息/工具 Schema 的 UTF-8 字节和输出额度保守预留；模型报告有效用量后回填。长上下文可能需要更高预算。
- USD 预算默认不启用。启用时角色必须固定模型并填写每百万输入/输出 tokens 的 USD 价格；换模型会清空旧价格。
- 价格、缓存折扣、服务端计量及外部工具费用可能不同。**这不是精确账单或绝不超额的保证**：当前请求可能已产生超过预留的用量；达到预算后阻止后续请求/工具步骤。
- 清理历史会移除基于这些记录的小时计数；活动任务组的预算记录不能被清掉。

## Git 工作树

在角色编辑中开启“使用独立 Git 工作树”。需要父级具备 Shell 能力、仓库已有 HEAD 且工作区干净。

- 不自动 stash、丢弃修改或执行项目 Git hooks；脏仓库直接拒绝。
- 工作树放在仓库 Git 元数据内的 `rikkahub-subagents/<任务UUID>`，使用 detached HEAD。
- 文件路径和 Shell 默认目录路由到该工作树。**这不是操作系统沙箱**；有 Shell 权限的模型仍能显式访问其他路径。
- 隔离角色必须是叶子，且由主对话直接派发。并行隔离写入请使用主对话的并行批次/工作流，不在隔离角色里继续递归。
- 结束后捕获补丁（包括新文件），记录哈希；应用时校验原始 HEAD、补丁完整性和 Git 冲突检查。
- 应用不会提交、不自动删除工作树。多个补丁逐项报告结果；失败/中断需检查实际状态，不能假设回滚。
- 每仓库最多保留 8 个托管工作树。核验、合并后请主动清理；应用不会为腾空间强删修改。
- 清理 App 任务记录不会删除工作区里的代码、工作树或补丁。

## 检查点与不确定状态

工具调用前先写入 `TOOL_IN_FLIGHT` 意图，确认完成后才保存带结果的安全检查点。

- 已完成调用的结果随子对话保存；恢复时继续剩余工作，不机械重复调用。
- 确认的只读操作、监督等待可重试。Shell、写入、派发等在途操作无法确认完成状态时标记 `UNCERTAIN`，不自动重放。
- 没有可验证检查点、模型/权限失效或上下文不兼容时报告受阻，而非擅自换模型或扩大工具权限。
- 祖先角色的权限限制也在恢复时重新校验；不能借恢复绕过祖先的只读或工具限制。
- 工作区 ID、目录及连接身份摘要必须匹配，防止把旧任务/补丁应用到更换后的服务器。
- 已保存的取消意图不会在重启时被当作可自动恢复任务。明确手动恢复是新的有界授权。
- Android 强制结束可能中断进程；取消无法撤回已发送请求，也不保证终止已经脱离会话的远端进程。不要依赖取消回滚文件变化。

私有目录：`files/subagents/`。记录不序列化 Provider 认证配置，但任务、上下文及工具输出可能敏感，勿随意公开。
任务结果约 32 KiB；日志单项约 256 KiB、单任务 8 MiB，日志总量限制 128 MiB；检查点单个 4 MiB，日志/检查点目录总量限制 256 MiB。截断明确标记。
保留最近终态及活动任务组；过期孤立日志会清理。持久化失败时停止新派发，不静默清空账本。
